# Forest Change Detection — QGIS plugin (CNN + CfC)

Выявление и классификация изменений лесного покрова по разновременным снимкам
Sentinel-2. **Маску изменения считает нейросеть** (компактная модель CNN +
двунаправленный CfC, бинарно «есть/нет», val F1 0.917, работает с 2–8 датами),
а тип изменения (вырубка/ветровал/пожар) классифицирует **TypeNet**
(дистиллированный DOFA-энкодер 12×768 + CfC 2×256, голова со сводками mean/last−first,
macro-F1 0.870 на val, строго по маске). Геообработка — GDAL/OGR, инференс — onnxruntime
(CPU или DirectML/CUDA, при ошибке — авто-откат на CPU).

## Как работает

1. **Маска (модель)**: для каждого чипа 32 px (320 м) строится временной ряд —
   сырой объём (T,6,32,32) reflectance/10000 (clip 0..1.5), dt (годы между датами)
   и doy (sin/cos DOY + год). Модель `masknet_v2_cfc.onnx` (MaskNet-v2 bicfcpn,
   1.69M параметров, T фикс. 8 с паддингом) выдаёт бинарно изменение/нет.
   Если дат больше 8, берутся 8 равномерно (первая и последняя сохраняются).
   Нелесные пиксели (SCL «не растительность»/вода, NDVI<0.3 на обеих крайних датах) → 255.
2. **Тип (модель)**: для изменённых чипов TypeNet из двух ONNX:
   - `typenet_encoder.onnx` — CnnDofaLike 7.58M: для каждой даты чипа (≤8) считает
     признак 768-d (λ-стем + 12 depthwise-separable слоёв, RF≈185 px, GAP);
   - `typenet_cfc.onnx` — TypeNetFeats 2.70M: concat(feats, doy, dt) → 2 блока
     двунаправленного CfC (ширина 256) + сводки mean/last−first → 3 класса; динамическое T (2–8),
     CfC на CPU.
3. Неизменённые чипы пропускаются без прогона сети типов (`no_change` не классифицируется).

## Возможности

- Режимы: **period** (мозаики `<дата>_<band>.tif` + `<дата>_SCL.tif`) и
  **files** (два multi-band GeoTIFF с 6 выбранными каналами).
- Выходные данные: `classes.tif` (0 no_change, 1 logging, 2 windfall, 3 fire,
  255 nodata), `changes.gpkg` (полигоны с `type`, `area_ha`), `summary.json`.

## Установка

Требуется QGIS 3.16+ (проверено на 3.44 LTR, Python 3.12).

**Вариант A — из ZIP (рекомендуется):**
1. скачайте `forest_change_plugin_v0.15.0.zip` из
   [Releases плагина](https://github.com/excelsllor/forest-change-qgis/releases);
2. QGIS → *Модули → Управление модулями → Установить из ZIP* → выберите файл;
3. включите модуль «Forest Change Detection (DOFA+CfC)».

**Вариант B — вручную:** скопировать папку `forest_change` в
`%APPDATA%\QGIS\QGIS4\profiles\default\python\plugins\` и включить модуль.

**Зависимости (один раз):**

```powershell
# Python из OSGeo4W (тот, что использует QGIS)
C:\Users\<user>\AppData\Local\Programs\OSGeo4W\apps\Python312\python.exe -m pip install onnxruntime
# опционально GPU: -m pip install onnxruntime-directml
```

**Модели (51.6 МБ) входят в ZIP:** `masknet_encoder.onnx` (5.5 МБ, λ-стем свёрнут), `masknet_cfc.onnx` (4.9 МБ, динамическое T),
`typenet_encoder.onnx` (30.3 МБ), `typenet_cfc.onnx` (10.9 МБ, динамическое T, CfC на CPU). Legacy-модель `forest_change_fusion128.onnx` (426 МБ, старая версия)
в ZIP не входит — при желании скачайте из Releases моделей. Чекпоинты для дообучения —
в репозитории [forest-change-model](https://github.com/excelsllor/forest-change-model) (v2.0).

## Как проверить

1. Откройте QGIS, загрузите снимки (мультиканальные GeoTIFF) → включите модуль → панель **Forest Change**.
2. Режим **«Загруженные снимки (слоты)»**: в слотах выберите нужные снимки из **уже загруженных слоёв проекта**
   (в списке видно дату), при необходимости добавьте слот кнопкой **«+ Добавить снимок»**.
   - `pre` = самый старый выбранный, `post` = самый новый; промежуточные даты (до 4) идут во временную ветку CfC.
   - Каналы подставляются автоматически по числу каналов файла (S2 L2A → 2,3,4,8,11,12; 6-канальный стек → 1..6).
   - Кнопка «Подставить два новейших» заполняет слоты двумя свежими снимками.
3. **Провайдер**: Авто / CPU / CUDA / DirectML (при недоступности или ошибке — авто-откат на CPU).
4. Укажите папку вывода и ONNX-модели → **«1. Посчитать маску (модель)»**, затем
   **«2. Посчитать изменение по маске (модель)»** или всё сразу.
5. Маска сразу рисуется красным на прозрачном фоне; классы — по типам (logging красный, windfall золотой, fire маджента); **Identify** по клетке показывает координаты, тип и уверенность.
6. Файлы в папке вывода: `mask.tif`, `classes.tif`, `changes.gpkg`, `cells.gpkg`, `summary.json`.

(Режим **«Готовые периоды (мозаики)»** — для наших мозаик `<дата>_<band>.tif` с 4 каноническими датами.)

**Ориентир (проверено на p3-мозаике, 2025-07→2026-06, 98 тайлов):** маска 14 112 чипов
(144.5 тыс. га) за 59 с; типы для 13 385 клеток — **177 с cold / 40 с warm** (кэш фич
энкодера в `out_dir/cache`, энкодер DirectML, CfC на CPU); выход — `classes.tif`,
`changes.gpkg`, `cells.gpkg`.

**Если в логе появилось `provider ... failed, falling back to CPUExecutionProvider`** —
это норма: плагин сам переключается на CPU, если выбранный провайдер не сработал.

**Скорость:** маска ~0.5 с/тайл (VRT 6-в-1 + кэш GDAL-хендлов + async-prefetch);
типы ~13 мс/клетка cold (энкодер DirectML ~2.4 мс/чип-дата, CfC на CPU) и **~3 мс/клетка
на повторном прогоне** (дисковый кэш фич `out_dir/cache`, ключ = даты + энкодер + mtime данных).
Для больших AOI выбирайте DirectML/CUDA.

## Точность

**Маска изменения (бинарно, bicfcpn_big + сводки + контекст 3×3 + length-aware CfC):**

| метрика | значение |
|---|---|
| val F1 (vozh, точные длины 2–4) | **0.929** (P 0.916 / R 0.942), p1/p2/p3 0.925/0.960/0.906 |
| clean-val (окна без пересечения кварталов) | **0.940** |
| GT p3 на сцене (через плагин) | P 0.966 / R 0.952 / F1 **0.959** |
| zero-vol (без снимков) | 0.008 — решения полностью из изображений |
| скорость (p3, 98 тайлов) | **59 с** (энкодер DML + CfC CPU, динамическое T) |

**Тип изменения (TypeNet, строго по маске; val, macro по присутствующим классам):**

| источник | macro-F1 | примечание |
|---|---|---|
| все (log/wind/fire) | **0.870** (0.922 / 0.877 / 0.983) | 9 875 val-сэмплов, голова со сводками |
| big4 (DISFOR) | 0.860 | 0.816 / 0.830 / 0.934 |
| california (пожар) | 0.972 | |
| vozh | 0.547 | log 0.944 / wind **0.698** |
| pairs / long | 0.920 / 0.939 | |

**Сквозная проверка на GT-чипах p3** (dataset.csv через ONNX-пайплайн плагина):
recall logging **88.1%** / windfall **93.6%**. `no_change` не классифицируется (его отсекает маска),
поэтому на ложных срабатываниях маски тип по умолчанию «windfall» — итоговая доля классов
на карте зависит от порога маски.

## Ограничения

- Маска не откалибрована по порогу (P 0.971 / R 0.718 на организаторах) — для повышения
  полноты можно понизить порог логита (argmax → diff > τ).
- Vozh windfall у TypeNet — 0.698 (было 0.474): вытянут головой со сводками; при желании можно
  дообучить под vozh (`ft_typenet_vozh.py` от честной базы).
- На ложных срабатываниях маски TypeNet отвечает «windfall» (no_change не обучен) —
  редкие типы на карте чувствительны к порогу маски.
